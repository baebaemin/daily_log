### [git] branch, worktree가 삭제돼도 커밋은 dangling 상태로 (어느 기간까진) 살아있다 

- 브랜치 이름은 커밋을 가리키는 포인터이고, 커밋 object는 git 저장소 안에 저장된 실제 데이터이다. 

```
main -> A -> B -> C
feature -> D -> E
```

- 이 상태에서 feature 브랜치 또는 worktree를 지우면

```
main -> A -> B -> C
D -> E
```

- feature 포인터는 사라졌지만 D, E 커밋 데이터가 즉시 삭제되는 것은 아니다. (로컬, 원격 둘 다 동일) 
- 해당 커밋들은 dangling/unreachable 상태로 남아있다가 git GC가 정리하기 전까지 저장소 안에 존재할 수 있다. 

### <hr/>

실수로 지워도 얼마 동안은 복구할 수 있으므로,

```
git reflog
git fsck --lost-found
```

같은 명령으로 커밋 해시를 찾은 뒤,

```
git branch recovered <commit-hash>
```

로 다시 브랜치 이름을 붙이거나 이용 중인 브랜치에서 cherry-pick 하면 된다.
