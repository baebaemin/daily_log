## Today I Learned

### [semantic-release] commit-analyzer releaseRules 커스텀하기 

- 디자인 시스템 버전 관리를 위해 버전 결정 및 릴리즈 진행 도구인 semantic-release를 사용 중이다. 

- 커밋 내용을 파악하여 어떤 버전을 올리지 판단하는 릴리즈 관련 플러그인 `@semantic-release/commit-analyzer`을 사용 중인데, 프리셋 미지정 시 Angular(conventional commits) 규칙을 쓰고 있다. 기본 `releaseRules`는 `lib/default-release-rules.js`에 하드코딩된 5개(breaking→major, revert→patch, feat→minor, fix→patch, perf→patch)다. 그 외 타입(chore/refactor/docs/style 등)은 릴리즈되지 않는다. 

- svg 아이콘 애셋을 추가하면서 minor 버전을 올리고 싶진 않았는데, 그렇다고 fix도 아닌 perf도 아니기에 `releaseRules` 옵션으로 커스텀 타입을 추가했다.
  ```js
  ["@semantic-release/commit-analyzer", {
    releaseRules: [{ type: "add", release: "patch" }], // 기본 feat→minor, fix→patch 등은 그대로 유지
  }]
  ```
- `add: ABC.svg 추가` 와 같은 커밋/MR 생성 후 릴리즈 할 때 patch 단위로 버전업할 수 있게 됨

### [semantic-release] commit-analyzer와 release-notes-generator의 분리된 역할 

- 문제 : 위의 내용처럼 커스텀 커밋 타입을 추가했는데 버전은 올라가지만 CHANGELOG/릴리즈 노트에 해당 내역이 안 남는 이슈 ... 

- 원인 : `commit-analyzer`와 `release-notes-generator`(커밋을 타입별 섹션으로 묶어 릴리즈 노트 텍스트를 생성) 두 플러그인이 각자 독립적으로 커밋을 파싱하고 "아는 커밋 타입 목록"을 따로 갖기 때문이었다.

- 해결 : CHANGELOG writer도 알 수 있도록 플러그인 옵션의 `presetConfig.types`를 수정. 단, 수정시 기존 목록에 merge되는 게 아니라 통째로 덮어씌워지므로 기존 타입까지 명시적으로 나열해야 한다.

- 예시 :
```js
module.exports = {
  plugins: [
    [
      "@semantic-release/release-notes-generator",
      {
        preset: "conventionalcommits",
        presetConfig: {
          types: [
            { type: "feat",   section: "Features" },
            { type: "fix",    section: "Bug Fixes" },
            { type: "perf",   section: "Performance Improvements" },
            { type: "revert", section: "Reverts" },
            { type: "add",    section: "Additions" }, // 커스텀 타입
          ],
        }
      }
    ]
  ]
}
```

### [git] push 옵션으로 MR까지 생성하기 

- 일반 `git push`는 원격 브랜치만 만들고 콘솔에 "New merge request" 링크만 출력할 뿐 MR을 만들지 않는다.

- 아래와 같이 push option을 쓰면 push와 동시에 MR을 생성하고 타겟 브랜치까지 지정할 수 있다.
  ```bash
  git push -o merge_request.create -o merge_request.target=develop -u origin feature/xxx
  ```
