### [CS] FE 주소와 BE 주소?
"BE 주소"라고들 하시길래 정확히 무슨 뜻인가 하고 찾아본 ... 

- php를 사용하는 구 메인 서비스에서는 php가 DB 조회 + html 조립 + 세션까지 다 처리해서 완성된 html을 리턴하는 구조여서 FE/BE 구분이 흐릿하다. 주소도 하나고, 세션 쿠키도 도메인이 직접 발급. 

- 이후 신규 서비스는 SPA + API 형식으로 개발되면서 FE/BE 책임이 분리됐다. SPA는 html을 새로 안 받고 JS가 갈아끼우는 방식이므로 바뀌는 데이터만 따로 받아올 API(=BE)가 필요해짐.
    - FE 주소 : 사용자가 브라우저로 보는 화면. (ex. Next.js가 렌더링하는 페이지, SPA ...)
    - BE 주소 : API 응답 + 인증, 세션 발급 서버

- 단, 역할 분리가 곧 도메인 분리와 늘 똑같진 않다. 같은 도메인에서 경로(/api)로만 나눠도 되고, 이곳은 도메인까지 분리해둬서 쿠키 공유와 리다이렉트 같은 장치가 추가로 필요한 것.

### [OAuth2] 3겹으로 중첩된 인증 시스템
런칭 앞두고 챙겨보지 못했던 파트 위주로 살펴보는 중... (특히 인증! 🙃) 근데 FE가 쿠키를 따로 저장하는 타이밍이 없다! 어디서 인증 책임이 일어나고 있는지 타고타고 가다가 이번 서비스는 복잡한 인증 시스템으로 구성되어있다는걸 알게되었다.

- 상황 : N개의 다양한 버티컬 서비스들이 기업 메인 서비스와 SSO 인증 체계를 공유하고 있다. 곧 런칭할 서비스 `굿빌더`도 SSO 인증 체계를 공유하기 위해 다음과 같은 과정을 거치게 된다.
    - [위임 방향] (쿠키가 심어지는 순서는 3 -> 2 -> 1)
        - (1) `굿빌더` 로그인 - OAuth2 클라이언트 (서비스 세션 쿠키 발급)
        - (2) `사람인` 통합인증 - SSO 인가 서버 (인증 쿠키 발급)
        - (3) `사람인` 로그인 - 실제 ID/PW 입력 화면 (PHPSESSID 쿠키 발급)

- 브라우저는 3개 쿠키를 다 저장하며, 다만 `굿빌더`가 사용하는 건 서비스 세션 쿠키 하나다. HttpOnly이므로 FE(JS)가 가공하지 못하고 BE의 Set-Cookie만으로 심어진다. FE는 리다이렉트만 유발하고, 저장은 브라우저만 함. 
- 리다이렉트를 타고타고.. 가면서 Set-Cookie가 3번 일어난다. 
- 타고타고 갈때마다 콜백 url을 넘겨서 다시 역순으로 되돌아올 수 있었던 것.

[쿠키가 심어지는 흐름]
1. 401이 나거나 쿠키가 없으면 buildLoginUrl 함수가 만든 주소로 window.location.assign 리다이렉트를 시킨다. 
    - buildLoginUrl 함수 : SSO 진입점 ({apiBaseUrl}/oauth2/authorization/saramin)을 base로 만들고, 로그인 후 돌아올 주소를 절대경로화 한 뒤 쿼리로 붙여 최종 로그인 URL을 반환.
    
2. SSO 진입점에 도착하면, 브라우저는 여러 서버를 302 리다이렉트로 타고 타고 로그인 화면으로 넘어간다. (콜백 주소도 챙김)

3. 로그인에 성공하면 PHPSESSID 쿠키를 발급한다. (= 이 브라우저는 사람인에 로그인된 상태라는걸 (3)의 로그인 서버가 기억하려고 심는 자체 세션 쿠키)

4. 인증 결과를 증명하는 code를 쿼리에 싣고 콜백 주소로 돌아감 - (2)의 통합인증에 전달

5. 마찬가지로 통합인증 전용 인증 세션 쿠키 발급하고, code 싣고 (1)로 돌아간다. 

6. (1)의 굿빌더 BE 콜백이 code를 받는다. 하지만 code만으론 로그인 확정이 아니다. BE가 통합인증 서버에 직접(서버-서버) code를 보내 토큰으로 교환·검증한다. - code는 쿼리로 노출되므로, 훔쳐도 쓸모없도록 브라우저를 거치지 않고 한 번 더 인증해야 함. 

7. 통합인증이 code를 검증해 유효하면 access token을 발급해 굿빌더 BE에 돌려준다. 굿빌더 BE는 그 token으로 사용자를 확인하고, 자기 자신의 서비스 세션 쿠키를 발급한다. 이때 access token은 BE에 남고 브라우저에는 서비스 세션 쿠키만 심긴다. 

8. 최초에 넘겼던 굿빌더 FE로 302 리다이렉트 (휴)

9. 이후 로그인 권한이 필요한 요청들은 브라우저에 서비스 세션이 있기 때문에 credentials: "include"로 자동 첨부된다.

- FE가 한 일은 1번의 리다이렉트 한 줄 뿐인데 인증/발급/저장/검증이 여러 서버를 오가며 이 과정을 통해 (사용자 입력을 빼면) 1~2초 안에 진행된다는 걸 알게되었다

### [Web API] window.location.assign
- 인자로 준 URL로 브라우저를 통째로 이동시킴 (= full page navigation)
- 현재 페이지를 떠나 새 주소를 서버에서 새로 로드함
- 로그인 URL처럼 Next router가 처리하지 못하는 주소이므로 router.push가 아니라 window.location.assign을 사용하는 경우가 있음.
