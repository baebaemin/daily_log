## Today I Learned

### [git] remote가 여러 개일 때 remote를 생략하고 push하면 의도치 않은 곳으로 갈 수 있다 

- 상황 : `origin`에 spec-kit으로 생성한 spec 문서를 관리하고 변경사항을 트래킹하기엔 양이 많아서 `fork`를 따서 spec 문서만 업데이트 하고 있었다. claude cli를 사용하다가 두 개의 remote가 설정된 저장소 root에서 `git push`를 remote 지정 없이 실행했더니 `origin`에 가야할 커밋이 `fork`로 가버렸다.

- 원인 : remote를 명시하지 않으면 upstream 설정을 따라가므로 가장 최근 접근한 곳이 `origin`이더라도 config값에 의해서 `fork`로 갈 수도 있다. 

- 해결 : remote가 둘 이상인 저장소에서는 push 대상 remote를 항상 명시한다(`git push origin <branch>`)

- 추적중인 upstream을 한눈에 보려면 : `git branch -vv` => 각 브랜치 옆에 커밋 해시값과 함께 [origin/develop], [fork/feature/req-specs] 형식으로 표기된다.

### [git] origin과 main 

- main: 내 컴퓨터에 있는 로컬 브랜치
- origin: remote 이름 (GitHub/GitLab 같은 원격 저장소를 가리킴)
- origin/main: 원격 저장소의 main브랜치를 내 git이 마지막으로 관측해둔 원격 추적 브랜치

그러므로 "main이 origin/main을 upstream으로 삼는다" = "로컬 main 브랜치가 원격 저장소 origin의 main 브랜치와 연결되어 있다"
