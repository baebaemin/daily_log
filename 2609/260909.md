## Today I Learned

### [Debug] JS 구조분해 기본값 관련 에러 개선

- 상황 : Sentry Error 개선 중 Cannot read properties of null (reading 'length')건의 TypeError가 한 달간 약 4,000여건 발생 중이었다. 

  ```jsx
    // 기본값을 []로 줬음에도 ... 
    const { data: userInfoList = [] } = useGetInfoList(
      {
        applyIdxList,
        seqList,
      },
      { enabled: !!applyIdxList || !!seqList },
    );

    const useInfo = userInfoList.length > 0 ? userInfoList[0] : undefined; // 에러 💥
  ```

- 원인1: 앱코드의 useGetInfoList는 공통 훅으로 useBaseQuery를 사용하는데, 여기서는 select로 `(data) => data.result` result를 리턴하도록 되어있다. 세션이 만료되었을 떄 서버가 `{ code, message, result: null }`을 주고, React Query의 data도 null이 된다. 

- 원인2: JS 기본 매개변수/구조분해 기본값은 `undefined`일 때만 적용되고 `null`에는 적용되지 않는다. `null`은 "값이 있는 상태"이므로 기본값을 밀어내고 할당된다! `null.length`이므로 TypeError가 발생

  ```jsx
  const { a = [] } = { a: undefined }; // a는 [] : 기본값 적용
  const { a = [] } = { a: null }; // a는 null : 기본값 무시
  ```

- 해결: 호출부에서 null과 undefined를 함께 안전하게 처리하는 옵셔널 체이닝으로 바꾼다.

  ```jsx
  const { data: userInfoList } = useGetInfoList(...);
  const userInfo = userInfoList?.[0];
  ```

- 이곳 말고도 `= []` 기본값에 의존하는 호출부가 여러 곳 있어 함께 고쳤다. 대부분 세션 만료 후 포커스 복귀 시나리오에서 드러나는 공통점이 있었다. QA에서 재현되기 어려운 경로라 프로덕션에서 처음 발견되었던 것 같다. 유사 케이스 센트리 에러 건 11건을 함께 수정하여 한 달에 약 4만 2천 건 발생하던 에러가 배포 후 사라졌을지 모니터링 예정
