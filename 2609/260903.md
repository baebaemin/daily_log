### [JavaScript] async/await

Web API인 [fetch()](../2402/240224.md#react-fetch)가 반환하는 Promise를 다루기 쉽게 만든 문법. 내부는 전부 Promise로 동작한다.

- async 함수는 항상 Promise를 return한다. 함수 안에서 return "abc"를 하면 실제로는 `Promise<"abc">`가 return된다.

```tsx
// async 함수 안에서 return하는 값은 JS 엔진이 그 값을 Promise에 담아서 반환한다. 
async function getName(): Promise<string> {
    return "abc";
}

const result = getName();
console.log(result); // Promise { "abc" } (문자열이 아님)
console.log(await result); // "abc" (await로 꺼내야 문자열임)

const p: Promise<string> = getName();
const s: string = await getName();
```

- 함수 안에서 Error를 throw하면 호출한 줄에서 즉시 예외가 터지고, Promise는 rejected가 된다.

```tsx
// 일반 함수 : Error를 throw하면 호출한 줄에서 바로 에러 발생
function normal() {
    throw new Error("실패");
}
normal(); // 여기서 에러 발생
```

```tsx
// async 함수 : Error를 throw 해도 호출한 줄은 정상 통과. 대신 rejected Promise가 반환됨
async function asyncFn() {
    throw new Error("실패");
}
const p = asyncFn(); // 여기서 에러 발생하지 않음. p는 Promise 객체.
console.log(p); // Promise { <rejected> Error: 실패 }
```

- return이 Promise.resolve(값)이라면, throw는 Promise.reject(에러)와 같다.

### [JavaScript] rejected Promise를 받는 쪽에서 에러를 꺼내는 두 가지 방법

throw된 에러는 Promise 안에 보관되어 있다가 await나 .catch()를 만나는 시점에 다시 밖으로 나온다. 

1. await + try/catch

    ```jsx
    // await가 rejected Promise를 만나면 그 에러를 throw로 되살림
    try {
        await asyncFn();
    } catch (e) {
        console.log(e.message); // "실패"
    }
    ```

1. .catch(): then 체인에서 잡기

    ```jsx
    asyncFn().catch((e) => console.log(e.message)); // "실패"
    ```

- 만약 아무도 await나 .catch()로 받지 않으면 "unhandled promise rejection"이 되어 콘솔에 경고로만 찍히게 된다. (잡지 않으면 그냥 조용히 지나감)
