## Today I Learned

### [TIL-WORDS]

- `라우터(Router)` : URL과 컴포넌트를 매핑하는 프레임워크 시스템

- `라우트(Route)` : 진입 가능한 URL

- `라우트 세그먼트(Route Segment)` : URL 경로에서 슬래시로 나뉘는 한 조각. Next.js App Router에서는 `app/` 아래 폴더 하나가 세그먼트 하나에 대응한다.

<br />

### [Next.js] 라우트 세그먼트라고 해서 다 라우트는 아니다

- 각 세그먼트는 자기만의 특수 파일을 가질 수 있고, 위에서 아래로 중첩된다.
    - `page.tsx` : 세그먼트의 화면. 이 파일이 있어야 해당 URL로 진입할 수 있다.
    - `layout.tsx` : 세그먼트와 모든 하위 세그먼트를 감싸는 껍데기
    - `loading.tsx` : 세그먼트의 Suspense 경계
    - `error.tsx` : 세그먼트의 에러 경계

```
applicant-view/                    ← 세그먼트지만 라우트는 아님
├── layout.tsx                     ← 하위 전체를 감싸는 레이아웃
├── (page.tsx 없음)                ← /applicant-view 진입 불가
├── [idx]/
│   └── page.tsx                   ← /applicant-view/123 진입 가능
└── position/                      ← page.tsx 없음, 경로 세그먼트 역할만
    └── resume/[resIdx]/page.tsx   ← /applicant-view/position/resume/456 진입 가능
```

- `applicant-view`와 `position`은 라우트 세그먼트이지만 라우트는 아니다. 진입은 불가능하고, `layout.tsx`로 하위 세그먼트를 감싸는 역할만 한다.

- 폴더 구조가 곧 URL이지만 "폴더가 있다 = 그 URL이 열린다"는 아니라는 게 핵심. 진입 가능 여부를 결정하는 건 `page.tsx`다.

### [React Query] "데이터를 라우터에서 가져온다"는 표현

- 데이터 페칭을 컴포넌트가 아니라 라우트 정의에 묶어서, 화면이 렌더되기 전에 라우트 전환 단계에서 가져온다는 뜻.

- App Router에서는 서버 컴포넌트인 `page.tsx`, `layout.tsx`가 여기에 해당한다. 컴포넌트 레벨이 아니라 라우트 세그먼트 레벨에서 페칭하는 것.

- 컴포넌트가 마운트된 뒤에야 요청이 시작되는 방식과 달리, 라우트 전환 단계에서 이미 요청이 시작되므로 렌더 → 페치 워터폴이 한 단계 줄어든다.

### [React Query] useQuery는 promise를 throw하지 않는다

- `useQuery`는 로딩을 `isPending`, 에러를 `isError`로 반환한다. promise를 throw하지 않기 때문에 상위 `Suspense` 경계가 걸리지 않고, 라우트의 `loading.tsx`도 뜨지 않는다.

- Suspense로 로딩을 처리하고 싶다면 `useSuspenseQuery`를 써야 한다. 이쪽은 내부적으로 promise를 throw해서 가장 가까운 Suspense 경계가 fallback을 띄운다. 에러를 ErrorBoundary로 올리려면 `throwOnError` 옵션이 필요하다.

- => 같은 데이터 로딩이라도 `useQuery`는 컴포넌트가 직접 분기해서 그리는 방식이고, `useSuspenseQuery`는 경계에 위임하는 방식
