## Today I Learned

### [JavaScript] throw는 어떤 값이든 던질 수 있다
문법적으로 throw 뒤에는 아무 표현식이나 올 수 있다.

```jsx
throw 'error';           // 문자열
throw 23892;                // 숫자
throw { code: 401 };     // 일반 객체
throw null;              // null
throw new Error('실패');  // Error 객체
```

위와 같이 무엇이든 던져질 수 있기 때문에 TypeScript에서는 catch (e)의 e가 unknown 타입으로 잡힌다. 그래도 관례상 Error 또는 그 하위 클래스를 던진다. 따라서 실무에서는 e instanceof Error로 확인한 뒤 e.message에 접근하는 패턴을 쓰기도 한다.

### [JavaScript] JS 내장 객체 Error
Error 객체에는 다음과 같은 정보가 포함되어 있다.
- stack : 어디서 던졌는지 추적할 수 있는 스택 트레이스. 
- message, name : 도구들이 표준으로 읽는 필드. Sentry 같은 에러 수집 도구는 Error가 아닌 값을 받으면 정보를 제대로 못 남긴다.
- instanceof 분기 : e instanceof TypeError처럼 종류를 구분할 수 있다.

### [JavaScript] try/catch
1. try/catch는 Error만 잡는 것이 아니라 throw로 던져진 것이라면 무엇이든 잡는다.
```jsx
try {
    throw "abc";
} catch (e) {
    console.log(typeof e); // "string"
}
```

2. 직접 throw하지 않아도 JavaScript 엔진이 내부적으로 던지는 에러도 같은 경로로 들어온다.
- undefined.foo 같은 잘못된 접근에서 엔진이 던지는 TypeError
- JSON.parse("잘못된 문자열")이 던지는 SyntaxError
- await가 rejected Promise를 만나 되살린 에러

3. 블록 안에서 동기적으로 던져진 것만 잡는다. 블록 안에서 시작한 비동기 작업이 나중에 실패하면 잡지 못한다. 때문에 try절 안에서 fetch가 있다면 await를 붙여야 잡힌다.

```jsx
try {
    // await 없으므로 실패해도 못 잡음 💥
    fetch("/api/x").then((r) => r.json()) 
} catch (e) { ... }
```

```jsx
try {
    // await 있음. 실패가 여기서 throw로 바뀌어 잡힘
    const r = await fetch("/api/x")
} catch (e) { ... }
```
