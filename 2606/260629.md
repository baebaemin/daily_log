## Today I Learned

### [TIL-WORDS] 
* `위저드(wizard)` : UI/UX 패턴 용어. 하나의 작업을 여러 단계(step)으로 나눠서 순서대로 진행시키는 화면 흐름. 화면 등이 분할되어 있어도 사용자 입장에서 논리적으로 "하나의 작업"이 된다.

* `딥링크(deep link)` : 사용자를 특정 앱으로 이동시켜서 원하는 화면을 보여주거나, 사용자 액션을 유도. 북마크나 주소창에 URL을 직접 입력해서 진입.

* `폴백(fallback)` : 원래 하려던 동작이 안 통하는 상황일 때 대신 실행하는 대안 경로.

### [Next.js] multi-step 위저드를 히스토리 1슬롯으로 설계하기 (push/replace/back) 

- 상황 : 공고를 등록하는 과정이 STEP-1~4로 쪼개져서 url이 분리된 상태이다. 해당 위저드에 진입한 뒤, 아무 스텝에서 뒤로가기를 누르면 공고 리스트로 이동한다.

- 문제 : STEP-N을 벗어난 상태에서 또 뒤로가기를 누르면 다시 이전 STEP-N으로 이동하고, 여기서 또 뒤로가기를 누르면 공고 리스트로 이동 ... 의 무한 반복이다. 멀티스텝 위저드 내에서는 이동과 이탈 모두 push였던 것이 원인 (리스트에서는 back으로 뒤로가기를 했으므로 스택에 쌓여있던 STEP-N으로 이동하게 되고, 다시 STEP-N에서 push로 리스트로 뒤로가기를 했으므로 스택에 다시 STEP-N이 쌓임)

- 해결 : 위저드 전체가 히스토리에서 1칸만 차지하도록 규칙을 통일 
  - 진입만 `push`(슬롯 생성)
  - 스텝 간 이동은 모두 `replace`(슬롯 내부 교체)
  - 이탈/완료는 `back`(슬롯 pop).

- 예시 :

```ts
// useHeaderBackGuard.ts
const leave = useCallback(() => {
  reset(); // router 동작과 별개로 폼 명시적으로 비워둠
  if (window.history.length > 1) {
    router.back(); // history가 있으니 슬롯 pop - 목록 복귀
    return;
  }
  // history가 없으면 리스트로 돌아가기
  router.replace(recruitRoutes.list(siteNo));
}, [reset, router, siteNo])
```

### [Web API] iOS Safari는 new Date() 파싱이 엄격함 

- 상황 : 특정 날짜 값이 갤럭시(Android)에서는 정상 노출되는데 아이폰(iOS)에서는 아예 표시되지 않는 ... 종종 마주쳤던 크로스 브라우저 버그

- 원인 : 서버가 공백 구분(`2026-06-29 12:34:56`)이나 점 구분(`2026.06.23`) 같은 비표준 포맷을 줄 때, Chrome/Android WebView는 관대하게 파싱하지만 Safari/iOS는 `Invalid Date`를 반환한다. (JS가 표준으로 보장하는 ISO 8601 형식은 구분자 T를 사용 `2026-06-29T12:34:56` -> 하지만 ECMA 스펙(Date.parse)은 ISO 8601 형식만 파싱을 보장하고, 그 외 형식은 엔진 구현에 맡기고 있다.) `Number.isNaN(date.getTime())` 가드에 걸려 빈 문자열이 렌더되어 값이 사라짐

- 해결 : `new Date()`에 원본 문자열을 그대로 넘기지 말고, ISO 형태로 정규화한 뒤 `date-fns`의 `parseISO`로 파싱.

- 참고 링크 : https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Errors/Invalid_date
