## Today I Learned

### [Agent Coding] Figma-to-Code 구현 품질 개선 > 테스트 기획

#### 1. 배경
최근 런칭한 서비스의 전 개발 과정에 (100-a)% 에이전틱 코딩 워크플로우를 도입했다. 그중 UI/UX 개발 과정에서는 Figma frame URL을 MCP로 연결하여, AI가 디자인을 읽고 구현했다. 일부 frame에는 Figma Code Connect가 적용되어 있어, AI가 실제 코드 컴포넌트의 경로와 props 사용 예시를 참고할 수 있었다.

그러나 Figma-to-Code 구현에서 AX 경험은 그닥 좋지 못했는데, 아래와 같은 이유 때문에 디자인 구현 품질이 일관적이지 않았다.

- 최상위가 서비스 전용 instance이면서 하위 구성 컴포넌트가 디자인 시스템(DS) instance인 경우 custom으로 구현하려는 확률이 높아짐

- Figma의 색상이나 간격 값을 그대로 해석해 hex color, spacing, radius를 토큰이 아닌 raw값으로 사용

- instance가 연결되어 있어도, variant 이름과 코드 props가 1:1로 대응되지 않아 잘못된 props 조합 생성

- Figma에 누락된 hover, focus, disabled, error 상태에 대한 지침 없을시 임의 구현

- code connect 누락

- Figma 내 디자인 컴포넌트가 정리되어있지 않음

이를 보완하기 위해 Figma MCP/Code Connect 워크플로우를 다듬어 디자인 시스템 준수율과 구현 일관성을 높이고자 했다.


#### 2. 목적
Figma MCP와 Code Connect만으로 AI 기반 UI 구현 품질을 충분히 확보할 수 있는지 검증하고, 부족한 영역이 확인될 경우 DESIGN.md로 보완한다. 이때, 해당 파일은 브랜드/제품의 시각 언어를 설명하기보다는 AI 구현 가드레일의 성격을 더 많이 띨 예정이다 (그러므로 DESIGN.md 파일명에 대한 고민도 필요해보임 - 하네스에 디자인 구현 지침이나 skill 등으로 흡수시킬수도)

- Figma instance와 Code Connect가 제공하는 매핑 정보를 실제 앱 코드 구현에 맞게 해석하는 기준을 검증

- AI가 임의 스타일, 임의 컴포넌트, raw hex, 임의 spacing을 생성하는 것을 방지

- Code Connect가 커버하지 못하는 예외 상황에서 판단 기준을 제공

- AI 기반 UI 구현 결과의 리뷰 비용 감소

#### 4. Figma MCP와 Code Connect가 있는데 DESIGN.md까지 필요할까?

#### 4-1. AI가 Figma 레이어 구조만 보고 불필요하게 분리 구현하는 경우가 있다.

- AI가 특정 DS instance가 아니라 상위 frame 전체를 보고 구현해서 Code Connect snippet을 놓치는 경우
- 하위 DS instance가 MCP 출력에서 약하게 잡히는 경우
- 기존 앱 코드에서 잘못된 패턴을 보고 따라 하는 경우


```tsx
    // 지양
    <Label>업체명</Label>
    <TextInput />
    <HelperText text="필수 입력 항목입니다." variant="error" />

    // 권장 - 아래처럼 TextInput의 props를 우선 사용
    <TextInput
        label="업체명"
        value={value}
        onChange={handleChange}
        isInvalid={hasError}
        errorText={hasError ? "필수 입력 항목입니다." : undefined}
        hintText={!hasError ? "사업자등록증 기준으로 입력해 주세요." : undefined}
    />
```

#### 4-2. Code Connect 커버리지가 완전하지 않을 수 있다.
- publish나 경로, 이름이 잘못 지정되거나 디자이너의 공수 부족(...) 등의 이유로, 모든 Figma 컴포넌트가 Code Connect로 연결되어 있지는 않다.
- 연결되어 있더라도 일부 props, slot, 상태, 이벤트 핸들러는 placeholder나 생략된 형태로 제공된다. 
- 이런 상황에서 AI가 직접 UI를 재구현하지 않도록, 우선 확인해야 할 컴포넌트와 fallback 규칙, 검증 방식 등을 제공해야 한다.


#### 4-3. 디자인 시스템 우회 방지
- Figma에서 적절한 instance mapping이 진행되지 않았을 경우, AI는 Figma와 비슷한 UI를 만들기 위해 다음과 같은 코드를 생성한다.

```tsx 
<button className={styles.primaryButton}>저장</button>

.primaryButton {
  background: #4876ef;
  border-radius: 10px;
  padding: 14px 20px;
}
```

#### 4-4. 기타
- Code Connect snippet은 import/props 매핑 기준으로만 사용하고, 이벤트 핸들러와 데이터 바인딩은 기존 앱 패턴을 따르도록 지시

- 최상위 Figma instance가 서비스 전용이어도 하위 DS instance는 디자인 시스템 코드 컴포넌트를 우선 사용

- Figma override는 raw style로 바로 반영하지 않고 token/variant/기존 예외 순서로 검토

- Figma frame에 없는 loading, empty, error, disabled 상태를 구현 전에 확인
