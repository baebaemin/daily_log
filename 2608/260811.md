> 이전 단계 : [테스트 기획](./260807.md#agent-coding-figma-to-code-구현-품질-개선--테스트-기획)

#### 환경
각 라운드 결과물끼리 서로 간섭하지 않도록 테스트별 브랜치 구축. 

- 1차와 2차의 차이는 Figma Code Connect 커버리지
- 3차는 저장소에 DESIGN.md가 있다는 점만 다르다. 에이전트가 알아서 집어가는지도 관찰 대상이므로 읽으라고 지시하지 않는다
- A화면과 B화면을 Claude Opus 5, Codex gpt 5.5 model으로 진행하여 총 6회의 figma-to-code 구현 테스트를 진행

#### 지시문
라운드마다 동일하게 전달한다.

```
<Figma URL>
이 화면을 apps/goodbuilder의 /create 경로에 구현해줘.
```

#### 판정 기준
- 2차에서 대부분 해소 → 보완 대상은 Code Connect
- 2차에서 남고 3차에서 해소 → DESIGN.md도 보완

### A-1 vs A-2

Code Connect 커버리지 보완 후 A-2 테스트를 진행했을 때 유의미한 수치들이 나왔다.

| 항목 | 1차 | 2차 | 변화 |
| --- | ---: | ---: | ---: |
| 구현 소요 | 18.3분 | 14.6분 | −20% |
| ├ 탐색·설계 | 10.9분 | 7.9분 | −28% |
| ├ 코드 작성 | 1.1분 | 0.9분 | − |
| └ 검증·보고 | 6.3분 | 5.7분 | − |
| 응답 턴 | 160 | 115 | −28% |
| output 토큰 | 115,281 | 83,463 | −28% |
| cache creation | 403,638 | 364,315 | −10% |
| 도구 호출 | 99 | 70 | −29% |
| ├ Bash | 66 | 56 | −15% |
| └ Read | 14 | 1 | −93% |

- 탐색 비용이 (특히 Read가) 14회에서 1회로 감소했다. 1차에서는 컴포넌트를 찾으려 파일을 열어봐야 했는데, 2차는 Code Connect가 알려줘서 그럴 필요가 없었음

- 1차에서는 BottomCta 구현시 매핑이 없어 Portal + BoxButton 2개로 직접 조립했는데, 2차는 @components/_layout/BottomCta를 그대로 사용했다.
