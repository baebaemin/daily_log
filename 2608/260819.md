## Today I Learned

### [Next.js] App Router의 정적(static) vs 동적(dynamic) 렌더링
- static : 미리 한 번 만들어두고, 요청이 오면 만들어둔 결과를 그대로 준다
    - static 라우트는 next bulid 시점에 컴포넌트를 실행해서 HTML과 [RSC](../2407/240703.md) 페이로드를 만들어 파일로 저장해둔다. 실제 요청이 오면 서버는 컴포넌트 코드를 전혀 실행하지 않고 저장된 결과를 반환한다. CDN에 캐싱할 수도 있고, `<Link>`가 뷰포트에 들어오면 브라우저가 prefetch할 수도 있어 클릭 즉시 전환된다.

- dynamic : 요청이 들어올 때마다 서버에서 새로 만든다
    - dynamic 라우트는 빌드 시점에 만들어둔 결과물이 없다. 요청이 도착하면 그때 서버가 layout부터 page까지 컴포넌트를 실행하고, 그 안의 await(쿠키 읽기, API 호출 등 ...)를 전부 기다린 후에야 응답을 만들어 보낸다. 즉, 페이지 이동시 서버 실행시간 + 데이터 페칭시간이 사용자 대기 시간으로 얹힌다.

따라서 인증 기반 앱은 루트 layout의 Providers가 Cookies()를 읽으므로 전 라우트가 dynamic이 될 확률이 높다. dynamic 라우트는 '요청마다 기다리는 시간'이 생기므로 loading.tsx(*예약된 파일명)의 스켈레톤, 스피너 등을 정의해주는게 좋다.
