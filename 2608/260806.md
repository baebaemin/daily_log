### [Figma] figma.connect(...) 선언이 담긴 *.figma.tsx

```tsx
/**
 * Chip 컴포넌트의 Figma Code Connect 매핑
 *
 * Figma 디자인 노드와 코드 컴포넌트를 연결한다.
 * props에 들어가는 건 "코드 컴포넌트의 prop 목록"이 아니라 "이 Figma 노드가 가진 프로퍼티" 쪽이다. 둘은 일치하지 않는다.
 */
import Chip from "@design-system/ui/Global/Chip";
import figma from "@figma/code-connect";

/**
 * Chip 매핑 (node-id 4104:40281)
 ** 배리언트 축 4개: Hierarchy, Size, Shape, Variant
 ** 컴포넌트 프로퍼티 2개: ● Chip Text(text), ○ Show Left icon(boolean)
 */
figma.connect(
  Chip,
  "https://www.figma.com/design/<FILE_KEY>/<FILE_NAME>?node-id=<NODE_ID>",
  {
    props: {
      hierarchy: figma.enum("Hierarchy", {
        primary: "primary",
        mute: "mute",
      }),
      size: figma.enum("Size", {
        sm: "sm",
        md: "md",
        lg: "lg",
        xl: "xl",
        xxl: "xxl",
      }),
      shape: figma.enum("Shape", {
        square: "square",
        round: "round",
      }),
      variant: figma.enum("Variant", {
        filled: "filled",
        outlined: "outline",
      }),
      chipText: figma.string("● Chip Text"),
      showLeftIcon: figma.boolean("○ Show Left icon", {
        true: "PlusLine",
        false: undefined,
      }),
    },
    example: (props) => (
      <Chip
        hierarchy={props.hierarchy}
        size={props.size}
        shape={props.shape}
        variant={props.variant}
        showLeftIcon={props.showLeftIcon}
      >
        {props.chipText}
      </Chip>
    ),
  },
);

/**
 * Chip with Avatar 매핑 (node-id 4374:48280)
 ** Hierarchy, Size, Shape, Variant, Chip Text
 */
figma.connect(
  Chip,
  "https://www.figma.com/design/<FILE_KEY>/<FILE_NAME>?node-id=<NODE_ID_2>",
  {
    props: { ... },
    example: (props) => (
      <Chip
        hierarchy={props.hierarchy}
        size={props.size}
        shape={props.shape}
        variant={props.variant}
        avatarImageUrl="image_url"
      >
        {props.chipText}
      </Chip>
    ),
  },
);
```

- code connect를 위해 작성하는 figma.connect의 `props`는 Figma -> 코드 단방향 매핑이다.
  1. Figma 프로퍼티가 있음 → `props`에 매핑. (`hierarchy` `size` `shape` `variant` `chipText` `showLeftIcon`)
  2. Figma에서 별도 노드로 존재 → 위의 예시처럼 Avatar가 포함된 Chip 유형이 있을 경우 `figma.connect`를 하나 더 선언. 
  3. Figma에 표현이 없음 → 미매핑. `onClick` 등의 핸들러가 해당될 수 있다.

- 즉 prop이 잘 매핑되었는지 판단하려면 code의 컴포넌트 타입이 아니라 figma 노드의 프로퍼티 목록과 대조해야 한다.

- 노드의 variant 축은 심볼 이름(`Size=md, Variant=filled, Shape=square, Hierarchy=mute`)으로 드러나지만, 텍스트·불리언 컴포넌트 프로퍼티는 나타나지 않는다. 대신, `●`(text) / `○`(boolean) 접두사로 구분하도록 내부적으로 합의.

### [Figma] Code Connect > 매핑 커버리지 100%가 성립하지 않는 이유

- code connect cli publish로 매핑 커버리지를 100%로 달성시키고 싶었으나 거의 실패하는중.. 수동으로 연결하려고 했더니 일부는 DS 소비 단위가 아니라서 연결할 필요가 없었다.

- code connect publish는 `figma.connect(...)` 선언이 담긴 `.figma.*` 파일만 올린다. Figma 레이어 트리를 따라 내려가며 자동 연결하는 방식이 아니므로 선언 없는 컴포넌트는 발행 대상이 아니다. 

- figma에서 감지되는 하위 컴포넌트는 두 종류로 나뉠 수 있다.
  1. 독립적으로 쓰이는 (Atomic의 atom 같은) DS 컴포넌트 (Icon, Button 등) 
    - 자체 `.figma.*`가 있다면 이미 발행되어 있다.
  2. 조립용으로만 만들어진 부품 컴포넌트 
    - 코드 베이스로 존재하지 않으므로 매핑할 게 없다. 

- 1번이 발행돼 있어도 부모 스니펫에 자동으로 나타나지는 않는다. 부모 컴포넌트에서 `figma.nestedProps` / `figma.instance` / `figma.children`으로 참조해야 한다. 그래야 소비처에서 부모 컴포넌트 하나를 통째로 쓰게 되고, 하위 DS 컴포넌트를 따로 조립하는 빈도가 낮아진다. 

- 위와 같은 이유로 Figma code connect UI가 보여주는 레이어 전부를 매핑하기는 힘들고, 화면 프레임에서 직접 사용되는 인스턴스 기준으로 정의해야 한다.
