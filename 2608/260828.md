## Today I Learned

### [Debug] 후보자 관리 페이지 flicker / layout shift / 로딩 지연 최적화

> 이전 : [React #482 에러 분석 및 개선 시도 ...](./260825.md)

무한 루프 방어용 Error를 해결하려 loading.tsx를 추가했다가 오히려 깜빡임 현상이 심해졌었다. 이전 버전으로 원복할까 고민하다가 페이지 전체를 최적화하기로 결정하고 flicker, layout shift, 로딩 지연을 함께 손봤다.

1. 서버 prefetch 병렬화 > `page.tsx`의 직렬 `await` prefetch 3건을 `Promise.all`로 전환시켜 #482 발생 가능 구간을 단축시켰다.

2. SPA이기 때문에 유지되었던 상태값을 날리기 위해 remount시키던 범위를 축소시켰다.

3. 중복 내비게이션 생략 > queryParams를 update하는 역할의 함수가 있는데, 쿼리가 기존과 같으면 router.replace를 생략해서 불필요한 라우터 dispatch를 제거했다.

4. lazy loading되는 DS Icon 200여종을 당장 정적 import로 변경시키기엔 영향 범위가 너무 넓기 때문에 (Atom 수준의 단위이기 때문) 앱 코드 내 아이콘이 포함된 좁은 범위마다 Suspense 경계를 추가했다. 

5. 반면, DS NoList의 경우엔 사용되는 illustㄹ를 정적 import화 하기로 이견없이 팀원들을 설득할 수 있었다. DS가 아닌 (= app에 종속된) 애셋들도 첫 화면에 등장할 확률이 높은 것들은 정적 import로 변경했다.

6. loading.tsx 도입 대신 하위 콘텐츠 뷰에 Suspense 경계를 추가했다. 

7. has-scroll 클래스로 폭 보정을 하느라 한 프레임씩 튀던 부분을 상시 적용되도록 수정했다.

#### [근본 원인 : 상위로 버블되는 design-system Icon의 suspend]

design-system의 `Icon`은 `next/dynamic`으로 아이콘 청크를 로드한다. 문제는 `ssr: true`이면서 `loading` 옵션이 없으면 자체 Suspense 경계를 만들지 않는다는 것.

```js
// next/dist/shared/lib/lazy-dynamic/loadable.js
const hasSuspenseBoundary = !opts.ssr || !!opts.loading
```

그래서 아이콘 하나의 첫 마운트 suspend가 가장 가까운 상위 경계까지 버블되고, 그 경계가 loading.tsx면 page 전체가 fallback으로 교체된다. 

<br />


#### [loading.tsx 삭제 이유]

기존 버전에서는 라우트 경계가 없어 이전 화면을 붙잡고 있었기 때문에 깜빡임 자체가 없었다. `loading.tsx`는 세그먼트의 page 전체를 감싸는데, 헤더(`TopInfo` + `ToolBar`)가 `page.tsx` 안에 있어서 라우트 전환마다 헤더까지 fallback으로 교체됐다. 

```jsx
<Page>                                   // async 서버 컴포넌트 — 서버 대기는 여기서 (경계 위)
  ㄴ<TopInfo/> <ToolBar/>                // 경계 밖 → 항상 유지
  ㄴ<Suspense fallback={...}>            // 콘텐츠 뷰에만
      ㄴ<PositionApplicantsManageView/>  // 커밋 이후 클라이언트 suspend를 여기서 흡수
```

page가 async 서버 컴포넌트라 서버 대기는 경계보다 위에서 끝나므로, 이 Suspense 경계는 라우트 전환 중에는 발동하지 않는다. 대신 커밋 이후 클라이언트 측 suspend(lazy Icon 등)만 흡수하는 안전망으로 동작하도록, 경계를 콘텐츠 뷰로 좁혔다.

<br />

#### [좁은 범위의 Suspense 배치]

fallback에는 실제 아이콘 크기(예: 추천 카드 아이콘 20px, 스페셜 태그 이미지 크기)를 예약해 layout shift도 같이 막았다. 경계를 너무 넓게 잡으면 다시 큼직한 영역이 깜빡여서 계속 pre-prod 배포 버전으로 화면을 확인하며 suspense 경계를 옮겼다. 사실 마음에 들진 않는 방식이라 Icon의 정적 import 방향을 다시 재고해보고싶다. (`was preloaded using link preload but not used` 경고도 계속 발생하고 있어서 같이 해결할 수도 있을 것 같다)
